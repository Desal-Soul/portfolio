02 — Lore

Contexte du projet


NO GAME NO LIFE est un projet réalisé en Terminale dans le cadre d'un travail de groupe. L'objectif était de créer une application regroupant plusieurs mini-jeux, chacun développé par un membre différent de l'équipe.

Chaque membre développait son jeu individuellement, puis tous les jeux étaient intégrés dans une application commune disposant d'une interface de sélection centrale — un véritable hub de jeux.

Ce projet a été l'occasion de mettre en pratique la programmation orientée objet et la gestion d'interfaces graphiques — en Tkinter pour le hub et le jeu de dames, en Pygame pour les jeux développés par les autres membres de l'équipe.

04 — Quête focus

Le Refactoring du Jeu de Dames


⭐ Code refactoré Fonctionnel → POO Tkinter

D'un code fonctionnel à une architecture orientée objet

Le jeu de dames existait déjà en Première : il fonctionnait, mais son code était un bloc de fonctions éparpillées, sans séparation claire entre la logique du jeu et l'affichage. Tout était mêlé dans le même fichier, difficile à faire évoluer ou à déboguer.

Le refactoring a consisté à restructurer entièrement ce code en classes distinctes — toujours en Tkinter, sans changer de technologie. Chaque responsabilité a été isolée dans sa propre classe : le plateau, les pièces, les règles du jeu, l'interface graphique. Le résultat est un code modulaire, lisible et maintenable.

▶ Avant (Première)
  • Un seul fichier, tout mélangé
  • Fonctions indépendantes sans lien
  • Logique et affichage couplés
  • Difficile à modifier ou déboguer
▶ Après (Terminale)
  • Classes Plateau, Pièce, Joueur, UI
  • Logique métier séparée du rendu
  • Code découpé, chaque classe = 1 rôle
  • Facile à lire, modifier, étendre
