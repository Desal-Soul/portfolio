Réalisation — Module de transfert de données

Étape 1 · Mission initiale
Conception du module

En début de stage, j'ai été chargé de concevoir un module permettant de transférer des données entre deux systèmes. L'objectif était de faciliter la synchronisation d'informations entre les différentes plateformes utilisées par l'organisme.

Étape 2 · Première version
Accès direct aux données — v1

Une première version fonctionnelle a été développée avec un accès direct aux données. Elle répondait techniquement au besoin initial, mais s'est heurtée à une contrainte externe majeure.

// v1 — lecture directe en base de données distante function fetchDataDirect($source) {   return $db->query("SELECT * FROM source_table"); }
Étape 3 · Contrainte externe
Blocage — intégration refusée

L'entreprise partenaire concernée ne permettait pas ce type d'intégration directe. Il a fallu repenser entièrement l'approche technique et repartir sur une nouvelle architecture.

🔗

Refonte du module — Intégration API REST

Étape 4 · Refonte complète
Développement via API REST — v2

J'ai redéveloppé intégralement le module en utilisant une API REST, respectant les règles d'accès imposées par le système externe.

// v2 — appel API REST avec authentification Bearer function fetchDataViaAPI($endpoint, $token) {   $ch = curl_init($endpoint);   curl_setopt($ch, CURLOPT_HTTPHEADER, [     'Authorization: Bearer ' . $token,     'Accept: application/json'   ]);   curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);   return json_decode(curl_exec($ch), true); }
Étape 5 · Bilan technique
Apports de cette refonte
  • Compréhension des échanges inter-systèmes via protocole HTTP
  • Structuration et gestion des requêtes API (headers, tokens, JSON)
  • Adaptation d'un développement aux contraintes techniques réelles
